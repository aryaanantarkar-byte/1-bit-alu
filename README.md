## Overview & Concept

In a computer processor (CPU), the **Arithmetic Logic Unit (ALU)** is the computational core. It takes digital inputs, performs mathematical operations (like addition or subtraction) or bitwise logical decisions (like AND, OR, XOR), and outputs the result.

```
             ┌──────────────┐
A ──────────→│              │
B ──────────→│    1-BIT     │────→ Result
Cin ────────→│     ALU      │────→ Cout
OP[1:0] ────→│              │
             └──────────────┘
```

---

## What is an ALU?

An **Arithmetic Logic Unit (ALU)** is a digital circuit responsible for all arithmetic calculations and Boolean logic checks within a computer. Modern CPUs contain 32-bit or 64-bit ALUs capable of executing billions of computations per second. Regardless of how wide (32-bit, 64-bit) an ALU is, every multi-bit ALU is conceptually built by combining **1-bit ALU slices**.

---

## What a 1-Bit ALU Does

A 1-bit ALU evaluates two 1-bit numbers (`A` and `B`), optionally considers an incoming carry (`Cin`), and performs one of four operations selected by a 2-bit code (`OP[1:0]`):

1. **AND** (`OP = 00`)
2. **OR**  (`OP = 01`)
3. **XOR** (`OP = 10`)
4. **ADD** (`OP = 11`)

It produces two outputs:
- **`Result`**: The 1-bit output of the selected operation.
- **`Cout`**: The 1-bit carry-out bit (active during addition when the sum exceeds 1 bit).

---

## Operations Breakdown

- **AND (`A & B`)**: Outputs `1` only when both `A` and `B` are `1`. Used for masking and checking specific conditions.
- **OR (`A | B`)**: Outputs `1` if at least one input (`A` or `B`) is `1`. Used for setting bits and combining flags.
- **XOR (`A ^ B`)**: "Exclusive OR." Outputs `1` if `A` and `B` differ (one is `1`, the other is `0`). Outputs `0` if both are identical. Fundamental to binary addition and parity checks.
- **ADD (`A + B + Cin`)**: Adds binary values together using standard binary arithmetic.

---

## The Full Adder Explained

A **Full Adder** is a foundational digital circuit that adds three single-bit binary values:
- `A` (Augend bit)
- `B` (Addend bit)
- `Cin` (Carry from a previous, less significant bit)

It yields two outputs:
- **`Sum`**: The unit-place bit of the sum.
- **`Cout` (Carry-Out)**: The two's-place bit of the sum (indicating an overflow of a single bit).

### Sum and Carry Meanings:
In decimal, $9 + 1 = 10$ (Sum is 0, Carry is 1).
In binary:
- $0 + 0 + 0 = 00_2$ (Sum = 0, Cout = 0)
- $0 + 1 + 0 = 01_2$ (Sum = 1, Cout = 0)
- $1 + 1 + 0 = 10_2$ (Sum = 0, Cout = 1) — the value 2 decimal cannot fit in a 1-bit digit!
- $1 + 1 + 1 = 11_2$ (Sum = 1, Cout = 1) — the value 3 decimal.

---

## Why Cin and Cout Exist

A single bit can only represent `0` or `1`. When you add `1 + 1`, the result is $2_{10}$ (binary `10`).
Because a 1-bit wire cannot hold `10`, the result splits:
- The low bit stays in **`Sum`** (`0`).
- The overflow bit moves into **`Cout`** (`1`).

`Cin` allows this 1-bit ALU to accept the `Cout` generated by a preceding ALU bit. By chaining `Cout` of bit 0 to `Cin` of bit 1, we can build 4-bit, 8-bit, 32-bit, or 64-bit adders!

---

## Boolean Equations & Operation Table

### Boolean Equations

1. **Full Adder Sum**:
   $$\text{Sum} = A \oplus B \oplus \text{Cin}$$
   *(In Verilog: `assign Sum = A ^ B ^ Cin;`)*

2. **Full Adder Carry-Out (Majority Function)**:
   $$\text{Cout} = (A \cdot B) + (A \cdot \text{Cin}) + (B \cdot \text{Cin})$$
   *(In Verilog: `assign Cout = (A & B) | (A & Cin) | (B & Cin);`)*

### ALU Operation Table

| `OP[1:0]` | Operation | Result Expression | Cout Expression | Notes |
|:---------:|:---------:|:-----------------:|:---------------:|:------|
| `2'b00`   | **AND**   | `A & B`           | `0`             | Logical AND; no carry generated |
| `2'b01`   | **OR**    | `A \| B`          | `0`             | Logical OR; no carry generated |
| `2'b10`   | **XOR**   | `A ^ B`           | `0`             | Logical XOR; no carry generated |
| `2'b11`   | **ADD**   | `Sum(A, B, Cin)`  | `Cout(A, B, Cin)`| Full binary addition |

## Hardware Architecture & Module Connections

In real digital logic, hardware is **concurrent**. All four sub-circuits (AND gate, OR gate, XOR gate, and Full Adder) compute simultaneously. A **4-to-1 Multiplexer (MUX)** steered by `OP[1:0]` routes the desired computation to `Result` and decides whether `Cout` is passed through or held at `0`.

```
                    ┌────────────────────────┐
                    │       alu_1bit         │
                    │                        │
  A ────────┬───────┼───► [ AND Gate ]───────┼──────┐
  B ────┬───┼───────┼───► [  OR Gate ]───────┼─────┐│
        │   │       │                        │     ││
        │   │   ┌───┼───► [ XOR Gate ]───────┼────┐││
        │   │   │   │                        │    │││
        │   │   │   │   ┌──────────────┐     │    │││  ┌───────────┐
  A ────┼───┼───┼───┼──►│              │-Sum─┼───┐│││  │           │
  B ────┼───┴───┼───┼──►│  full_adder  │     │   │││└──┤00 (AND)   │
Cin ────┼───────┴───┼──►│              │-Cout┼─┐ └───┤01 (OR)    ├─► Result
        │           │   └──────────────┘     │ │  └──┤10 (XOR)   │
        │           │                        │ │  └──┤11 (ADD)   │
        │           │                        │ │     └─────┬─────┘
        │           │                        │ │           ▲
        │           │                        │ │           │ OP[1:0]
        │           │                        │ └─────────┐ │
        │           │                        │           ▼ │
        │           │                        │     ┌───────────┐
        │           │                        │  0 ─┤00, 01, 10 ├─► Cout
        │           │                        │     │11 (ADD)   │
        │           │                        │     └───────────┘
        │           └────────────────────────┘
```

## How to Compile & Simulate (Icarus Verilog)

Open VS Code terminal or PowerShell inside the `1-bit-alu` folder:

### 1. Compile the Verilog files:
```bash
iverilog -o alu_sim src/full_adder.v src/alu_1bit.v tb/alu_1bit_tb.v
```
*(If `iverilog` is not in your system PATH on Windows, call: `& "C:\iverilog\bin\iverilog.exe" -o alu_sim src/full_adder.v src/alu_1bit.v tb/alu_1bit_tb.v`)*

### 2. Run the simulation:
```bash
vvp alu_sim
```
*(Or `& "C:\iverilog\bin\vvp.exe" alu_sim`)*

### Expected Output:

## How to Inspect Waveforms (GTKWave)

Open the generated VCD waveform file in GTKWave:

```bash
gtkwave alu_1bit.vcd
```
*(Or `& "C:\iverilog\gtkwave\bin\gtkwave.exe" alu_1bit.vcd`)*

### Waveform Signals to View:
In GTKWave:
1. In the upper-left panel (SST), expand `alu_1bit_tb` and click `dut`.
2. Select the signals:
   - `OP[1:0]`
   - `A`
   - `B`
   - `Cin`
   - `Result`
   - `Cout`
3. Click **Append** or drag them into the Signals display.
4. Click **Zoom to Fit** (or press `Ctrl + Shift + F`) to see all 32 transitions across simulation time!

## What You Learned From This Project

1. **RTL Modeling**: How hardware description differs from software; logic gates compute concurrently rather than sequentially.
2. **Dataflow Modeling (`assign`)**: Using continuous assignments to describe combinational circuits like the full adder.
3. **Behavioral Multiplexing (`always @(*)`)**: Modeling combinational MUX routing using `case` statements.
4. **Hierarchical Design**: Instantiating submodules (`full_adder`) inside higher-level modules (`alu_1bit`).
5. **Self-Checking Testbenches**: Writing structured testbenches that automatically evaluate expected results vs actual outputs and report PASS/FAIL instead of relying on manual waveform inspection.
6. **Waveform Tracing**: Generating and reading VCD files with GTKWave to trace gate transitions over time.

## Next Step: Scaling to a 4-Bit ALU

To scale this to a 4-bit ALU (`A[3:0]`, `B[3:0]`, `Result[3:0]`):
- Instantiate **four 1-bit ALUs** (`ALU0` to `ALU3`).
- Broadcast the same `OP[1:0]` to all 4 slices.
- Connect `Cin` of `ALU0` to external carry-in.
- Chain `Cout` of `ALU0` into `Cin` of `ALU1`, `Cout` of `ALU1` into `Cin` of `ALU2`, and `Cout` of `ALU2` into `Cin` of `ALU3`.
- `Cout` of `ALU3` becomes the final multi-bit Carry-Out.
